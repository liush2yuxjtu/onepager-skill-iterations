Skill-Creator · 评测驱动迭代 · Pitch

三个火种，一套循环Three sparks, one loop

我们没把技能"一次写对"。三个真实的翻车点成了火种，用 /skill-creator 一套循环反复烧：每遇到 1 个问题 → 生成 1 类多个评测 case → 我们打分+评语 → 它自己迭代。结果：/onepager 从 v0 通过率 63.9% 迭代到 v1 的 100%。

v0 63.9%→v1 100% 17 evals14 法则3 轮 iteration
结论 · TL;DR

先用 /skill-creator 建一个能跑的 baseline，然后每次出现 1 个新问题，就让它提示并修改技能、生成 1 类多个 case、我们打分 + 写评语、它自己迭代提升性能。反复 4 轮，onepager 的通过率从 63.9% 到 100%，同时每轮都更省时省 token。本页就是这套循环的证据 + 教程。

壹 · 初心
01

三个火种 — 我们到底想改什么

不是抽象的"更好"，是三个具体的痛。每个火种后来都沉淀成了法则 + 一类评测。

Ⅰ

千行 HTML：费 token，一处错全崩

naive 版爱写一个千行 HTML：每次迭代都要重读重写，token 烧穿；任何一处标签写错，整页渲染失败。

想改成：几百行框架 + 每个要展示的地方单独一个 sub-artifact HTML，产物链接 inline 在主页里。

→ 法则 8 main+subs · 法则 7 归集 · 法则 11 内联可见
→ evals 3, 5-10
Ⅱ

不画 SVG：改个 icon 就重生成整页

naive 版用 HTML/文字讲数据、甚至不画；改网页里一个小 icon，就触发重写整份 HTML，太烧 token。

想改成：主动手写 SVG 画数据 & UI mock——SVG 很小但信息量丰富，改动局部不影响全局。

→ 法则 11 内联默认 · 法则 12 SVG 主动绘制（mock up）
→ evals 11-15
Ⅲ

输密码 / key 就卡手

需要人类填密码、API key、验证码时，页面卡住、不知道填什么、填完还要手动回传给 agent。

想改成：一键打开链接 → 复制凭据进页面 → 一键把所有密钥 + 人工输入复制成一个 prompt 回传 agent。

→ 法则 13 HITL 凭据窄门（安全可复制不卡死）
→ evals 16-17

陆 · Runner
06

同一套循环，跑在任何 runner 上 — pi -p 与 claude -p

skill-creator 的评测循环与 runner 解耦。我们用的是 Pi 的 headless print 模式，等价的 claude -p 一样跑同一套 evals。

pi --print --mode json --no-session --no-context-files --no-extensions --no-skills \ --skill ~/.agents/skills/onepager --provider openai-codex --model gpt-5.6-sol \ --thinking medium "<评测任务 prompt>"

pi -p · pi --print

我们实际用的 headless runner：加载指定 skill、跑评测、输出 JSON 流，脚本自动评分（run_eval*.py）。

claude -p · claude --print

等价的 headless 模式：同一份 evals.json、同一套打分脚本，换 runner 即跑。
