二、核心发现

  1. Top 5 SQL 吃掉 Top 20 总耗时的 47%——其中 #1 订单深分页查询单条占 19%，是最大单一瓶颈（P0）。
  2. 12/20 慢 SQL 缺失复合索引，可通过单条 CREATE INDEX 立即解决，预计降低慢查询耗时 40%~55%。
  3. 深分页问题集中在 order_info / operation_log：大 OFFSET + ORDER BY ... DESC 触发全表扫描 + filesort。
  4. 报表重复计算：report_flow 同一聚合每天跑 3 次，可改为增量或缓存。
  5. 批量写入以单条 INSERT 循环执行（coupon_claim，每次 500 次往返），应改为批量 VALUES。
  6. 高峰时段集中：慢查询在 14:00–18:00 陡增，峰值为凌晨低谷的 15 倍（详见趋势页）。
