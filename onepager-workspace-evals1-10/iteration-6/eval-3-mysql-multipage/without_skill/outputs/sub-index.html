索引优化建议

12 条可直接执行的 DDL，均对应 Top 20 慢 SQL；执行前请在低峰期验证。

新增索引清单

预估收益为「该 SQL 扫描行数 / 平均耗时」的粗略降幅，需上线后以 slow_query_log 复核。
#DDL 建议服务 SQL预估收益风险
1ALTER TABLE order_info ADD KEY idx_status_created (status, created_at);#1、#10扫描 184 万 → 数千行，耗时 -70%低
2ALTER TABLE operation_log ADD KEY idx_biz_log (biz_type, log_time);#5扫描 978 万 → 数十万行中（表大）
3ALTER TABLE product_sku ADD KEY idx_brand_category (brand_id, category_id, sale_count);#4全表 → 命中索引，去除 filesort低
4ALTER TABLE refund_order ADD KEY idx_merchant_id (merchant_no, id);#10深分页扫描量大幅下降低
5ALTER TABLE member_coupon ADD KEY idx_member_status (member_id, status);#11过滤后行数降到个位低
6ALTER TABLE ad_campaign_stat ADD KEY idx_date (date, click, impression);#12聚合走覆盖索引，去 Using temporary低
7ALTER TABLE cart_items ADD KEY idx_user_updated (user_id, updated_at) INCLUDE (product_id, qty);#13覆盖索引避免回表 + filesort低
8ALTER TABLE promotion_rule ADD KEY idx_active_time (is_active, start_time, end_time);#16表达式改等值+范围，命中索引低
9ALTER TABLE logistics_track ADD KEY idx_waybill_event (waybill_no, event_time);#18组合条件命中，排序走索引低
10ALTER TABLE merchant_settle ADD KEY idx_settle_merchant (settle_date, merchant_id);#19过滤行数降到个位低
11ALTER TABLE product_review ADD KEY idx_product_created (product_id, created_at);#20排序走索引，分页扫描量下降低
12ALTER TABLE order_detail ADD KEY idx_order_id (order_id);#3、#17JOIN / 大 IN 聚合命中索引低

索引之外：需要应用层改造的问题

加索引无法解决，需代码改造（详见 DBA 行动清单）。
SQL问题建议方案
#1 / #10 / #20深分页 OFFSET 大值改为 keyset 游标（WHERE created_at < 上一页最后一条 ORDER BY ... LIMIT 20）
#2高频 UPDATE 行锁争用错峰/批量合并更新，或按 user_id 分片分散锁
#6单条 INSERT 循环 500 次INSERT ... VALUES (..),(..),.. 批量提交
#7 / #17大 IN 列表拆分 IN 为 ≤100 的批次，或改为临时表 JOIN
#8报表重复计算改为每日增量汇总表 + 结果缓存
#15隐式转换应用层把 order_no 传参改为字符串
#5SELECT * 返回大字段收敛为需要的列
上线注意：operation_log 表约 1,200 万行，DDL 会持有写锁，务必用 pt-online-schema-change 或 MySQL 8.0 INSTANT/DML 兼容方式在低峰期执行，并先压测。
