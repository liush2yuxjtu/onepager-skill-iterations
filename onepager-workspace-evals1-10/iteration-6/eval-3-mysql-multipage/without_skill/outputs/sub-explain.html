从 Top 20 中选取 6 条代表性慢 SQL，逐条解读执行计划与根因。

阅读说明

关注三个信号：type=ALL（全表扫描）、key=NULL（无索引可用）、Extra 中 Using filesort / Using temporary（排序/聚合未走索引）。

#1 · order_info 深分页查询 P0

SELECT * FROM order_info
WHERE status = 0 AND created_at BETWEEN '2026-08-01' AND '2026-08-07'
ORDER BY created_at DESC LIMIT 20 OFFSET 12000;
idselect_typetabletypepossible_keyskeyrowsfilteredExtra
1SIMPLEorder_infoALLNULLNULL1,840,2325.0%Using where; Using filesort
诊断：没有 (status, created_at) 复合索引，优化器选择全表扫描 184 万行；OFFSET 12000 需先跳过 12000 行再取 20 行，叠加 filesort。深分页是慢的主因，索引只能解决「过滤 + 排序」，深分页需改 keyset 游标。
