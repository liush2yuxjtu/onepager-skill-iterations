加载时的 fail-closed 校验

  • 版本不认识：忽略快照，进入空白聊天，不阻断 Web 启动。
  • 对象已删除：丢弃对应线程，避免路由到不存在的专家/员工。
  • 流式中断：streaming=false，保留已收到文本并标记“刷新前响应未完成”。
  • Session 超时：历史仍可读；下一次发送由现有后端显式提示“原会话已过期，已开启新上下文”。
  • 容量不足：先删 30 天前，再按最旧线程裁剪；仍失败则停止保存并给非阻塞提示。

06 · 风险与边界

不把“刷新不丢”膨胀成聊天平台

风险 可能性 控制
localStorage 超配额 中 30 天 + 50 线程 + 100 消息/线程 + 约 2 MiB；按最旧裁剪。
刷新发生在流式响应中 中 250ms 防抖保留已见文本；恢复后明确标“响应未完成”，不伪装完成。
旧 sessionId 对应 Sandbox 已销毁 高（10 分钟后） 沿用当前 fail-closed 语义；历史可读，后端显式开启新上下文。
消息中误贴敏感值 低/高影响 不保存工具详情与附件；沿用“凭据只经 Credential MCP”规则；删除会话即删除本地快照。
多标签页互相覆盖 低 本轮不支持；出现真实需求再加 storage 事件和 revision，而非现在预建。

明确做

  • 刷新后恢复会话列表、消息、当前线程、已加入上下文。
  • 短时间刷新后继续使用仍存活的 sessionId。
  • 删除、损坏、超限和中断都有确定行为。

明确不做

  • 不做账号、跨设备、云同步、全文检索。
  • 不把 Cloud Agent SDK JSONL 当成 UI transcript。
  • 不引数据库、IndexedDB 封装或第三方状态库。
