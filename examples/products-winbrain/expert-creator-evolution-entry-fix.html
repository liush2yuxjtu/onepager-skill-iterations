UX decision · smallest safe fix

不要让用户猜“切换工作对象”会不会进化专家。

当前行为不是后端坏了：新建模式的 Creator Sandbox 按设计看不到宿主专家目录；真正的问题是 UI 把“普通对话”和“进化已有专家”藏在两个不同入口，却没有在创建师会话里说明。

推荐 A
显式模式切换 + 复用现有进化链路

在专家创建师会话中显示当前模式，并提供「选择已有专家进化」按钮。选择目标后仍走现有确认框、Creator Chat Port 和隔离 Sandbox；不新增 API、数据库、依赖或宿主目录读取。

01 · diagnosis

用户没做错，入口语义错了

截图中的线程标题已经给出证据：它是「创建新专家」，不是「进化某专家」。

现在

创建师会话里只有「更换工作对象」。选专家会开始普通业务对话；继续问创建师，它仍处于空白 create Sandbox。

创建新专家线程 ├─ 更换工作对象 → 普通专家对话 └─ 问“有哪些专家” → Sandbox 无宿主目录权限 结果：用户以为已选择进化目标，实际没有

修复后

创建师上下文直接标出「新建模式」，另给独立的「选择已有专家进化」动作；普通对话入口仍保留。

专家创建师 · 新建模式 ├─ 继续新建专家 ├─ 选择已有专家进化 → 目标确认 → 进化线程 └─ 切换普通对话 → 与专家对话 结果：每个按钮只表达一个动作
02 · interaction

两个模式，两个明确路径

切换标签查看建议的用户路径。进化模式只列出在职、非平台专家。

1 · 模式标识专家创建师 · 新建专家
2 · 描述需求继续当前 create 线程
3 · 生成草稿空 Sandbox 创建 Plugin
4 · 测试发布沿用现有 Creator 流程
1 · 显式按钮选择已有专家进化
2 · 安全过滤在职 + 专家 + 非平台资产
3 · 目标确认复用进化草稿名称对话框
4 · 隔离进化seed Plugin 副本，线程标题「进化 X」
03 · clickable prototype

直接点一遍修复后的入口

这是交互提案，不连接真实 API。点击绿色动作，完整体验从 create 到 evolve 的模式转换。

04 · implementation

修在入口，不扩大模型权限

最小根因修复：前端明确选择 intent，现有后端已经支持 create / evolve。

1
创建师上下文条
当 CHAT.oid === "skill-expert-creator"，显示模式徽标；create 线程展示「选择已有专家进化」。
2
专用进化选择器
增加 picker purpose evolve；只展示 lifecycle active、level 专家、非平台专家，按钮文案为「进化此专家」。
3
复用已有链路
选择后调用 openEvolveConfirmById(id)，确认后继续调用 openCreatorConversation("evolve", id, name)。
4
不做的事
不让模型扫描 workspace/experts；不解析“帮我进化 X”自然语言；不动态改写正在运行的 Sandbox target。
