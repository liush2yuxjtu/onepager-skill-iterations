一句话本质：Agent SDK 是 Claude Code 的库化版本——agent loop（规划→工具→上下文管理）已在内部跑完，你的进程只负责输入 prompt、收流式消息、挂 hooks/MCP/权限。winBrain 已用其中 60%（MCP / hooks / 权限 / 会话 / 系统提示 / 沙盒），缺口集中在 结构化输出 / Checkpointing / OTel / Tool Search / 子代理。

Agent loop（消息生命周期）

  • 你的进程 → SDK 子进程（Claude Code 内核）→ 模型 API；往返流式消息
  • 循环内自动处理：工具调用 → 工具执行 → 结果回填 → 继续推理，直到停止条件
  • 上下文管理（压缩）、错误结果（error_max_turns 等）、会话持久化全部内置

两种输入模式

模式 用法 适合 限制
Streaming Input（推荐） ClaudeSDKClient（Py）/ 持续 session（TS），先发首条消息、等待条件、再追图/追问 交互式多轮、需要中途追加图片/文件、长会话 需要自己管理生命周期
Single Message query(prompt, options) 一次性调用，返回消息流 单轮任务、无状态 API、脚本自动化 单条 prompt 定生死；错误结果会抛异常；继续对话要靠 session_id 
// 单轮 query（winBrain 当前用法）
for await (const message of query({ prompt, options })) { … }

6 个核心导出函数

函数 作用
query(prompt, options) 单轮查询；流式产出 assistant 消息与 result 消息；错误结果抛异常
queryStream / 流式接口 实时流式响应（文字 + 工具调用逐条到达），供 UI 逐字渲染
startup(options) 前台交互式 agent 会话（终端式），把 stdin/stdout 交给用户
tool() 定义自定义工具（含 ToolAnnotations：只读/敏感/破坏性标注）
createSdkMcpServer() 把自定义工具打包成进程内 MCP server（本地工具的标准姿势）
listSessions() / getSessionMessages() 列出/读取历史会话消息（审计、恢复、UI 历史）

Options 关键字段（配置面）

  • model — 模型路由；systemPrompt — 系统提示（预设 claude_code 或自定义）
  • mcpServers — MCP 注册表（stdio / HTTP / SDK 内建）
  • permissionMode — 权限模式；allowedTools / disallowedTools — 工具白/黑名单
  • hooks — 事件拦截表；checkpoint — 文件回滚开关
  • env — 子进程环境（winBrain 强制 {}，不继承宿主）
  • settings — Claude Code 配置（含 apiKeyHelper 等启动例外）
  • sessionId / resume / continue / fork — 会话控制
  • cwd — 工作目录；executable — CLI 路径

hooks 配置特性

  • Matchers：按工具名过滤（如只拦 Write/Edit）
  • 回调可返回：修改工具输入、注入上下文、阻止执行（hookSpecificOutput.block）
  • 异步输出：可启动后台任务立即返回（用于审计管道）
操作 语义 典型场景
continue: true（TS）/ 自动 client（Py） 同一会话自动续聊 连续对话（winBrain 的热加载聊天）
resume: sessionId 按 ID 恢复旧会话 崩溃恢复、/resume 语义（winBrain AgentBay 已做）
fork: sessionId 从某会话分支出新会话，原会话不动 探索备选方案、A/B 实验
外部存储（session-storage） 镜像到 S3 / Redis / 自有后端 多主机恢复、审计、跨部署迁移

官方 API

  • listSessions() → SDKSessionInfo[]；getSessionMessages(sessionId) 读取任意历史
  • result 消息携带 session_id / checkpoint_uuid，先存后用于恢复

自定义工具（in-process MCP）

  • 推荐路径：tool() 定义 → createSdkMcpServer() 打包 → 注册进 mcpServers
  • ToolAnnotations：readOnlyHint（只读）/ destructiveHint（破坏性）/ sensitiveHint（敏感）→ 影响权限评估
  • winBrain 的 winbrain_credentials MCP 即此模式（每次读取需填写用途）

外部 MCP：3 种传输

传输 说明 winBrain 现状
stdio 子进程启动，本地私有工具 ✅ 本体/外部 MCP stdio
HTTP / SSE 远程服务器（可带认证） ✅ Data Ontology MCP HTTP 版
SDK MCP servers 进程内直接挂载 ✅ 自定义工具

Tool search（大规模工具检索）winBrain 未用

  • 目录上限 10,000 个工具；按需检索，每次返回最相关 ≤5 个
  • 模型要求：Sonnet 4.5 / Haiku 4.5 / Opus 4.5 及更新
  • 价值：AgentBay 白名单 10 个工具靠人工维护；未来专家工具膨胀时可切换检索式
  • 优化：工具名/描述写清晰（检索质量 = 描述质量）

Structured output winBrain 未用

  • 多轮工具调用后，返回经过验证的 JSON（JSON Schema / Zod / Pydantic）
  • result 消息携带 structured_output，类型安全直出业务数据
  • 失败类型：error_max_structured_output_retries → 可重试/降级
  • 示例：TODO 提取 agent（Grep 找 TODO + Bash git blame 后输出 JSON 清单）
  • winBrain 落点：专家 API 响应校验、本体导入草稿结构化、业务 App 数据契约 
// 定义 schema → 结果自动校验
const result = await query({ prompt, options: { structuredOutput: mySchema } });

审批与用户输入（can_use_tool / AskUserQuestion）

  • can_use_tool 审批回调：展示工具请求 → 用户 allow/deny → 放行或阻止（可改写输入）
  • ⚠️ 已知 workaround：需要 dummy hook 保持流开启才能收到 can_use_tool
  • AskUserQuestion 澄清问题：结构化选项（TS 支持选项预览），用于信息不足时提问
  • winBrain 现状：PreToolUse 门禁已有；can_use_tool 审批流 + AskUserQuestion 未接入 UI

流式响应

  • 文字与工具调用逐条实时到达 → 适合逐字渲染（chat-renderer 可升级为流式打字机）
  • Vercel AI SDK 的 useChat 是同一体验的前端封装，可混用
模式 行为 适用
default 按工具规则提示确认 交互式终端
acceptEdits 文件编辑免确认 受控沙盒内自动修文件
dontAsk 不询问，按 allow/deny 规则放行 自动化流水线
bypassPermissions 全部放行（仅限沙盒内！） 🔒 winBrain Sandbox B：只在 OS Sandbox + 路径门禁双保险内使用，绝不绕过沙盒本身
plan 只读规划，不执行 方案评审
  • allow/deny 规则：声明式（如 Bash(npm run *)）或 hooks 回调式（如 winBrain 的 PreToolUse 路径门禁）
  • 模式可会话中途动态切换（如先 plan 后 acceptEdits）

Checkpointing（文件回滚）winBrain 未用

  • 开启后：首条消息返回 checkpoint_uuid + session_id
  • Rewind：resume 会话 + 空 prompt → 文件恢复到该检查点
  • 模式：风险操作前打点、错误/校验失败自动回滚、多恢复点（存 checkpoint 元数据）
  • winBrain 落点：专家改文件失败 → 自动回滚到回合前，双保险叠加沙盒隔离

OpenTelemetry winBrain 未用

  • 导出 traces / metrics / log events 到任意后端（OTLP）
  • traces 在 beta，需显式开启；可关联应用上下文（用户属性）、控制敏感数据脱敏
  • winBrain 落点：接现有 herdr 监控 / SLS，trace 每步 agent 调用

成本追踪（cost-tracking）

  • token 用量四维：输入 / 输出 / 缓存读写（cache tokens，TTL 可扩到 1h）/ 每步 per-step、每模型 per-model
  • 单 query 总成本、跨调用累计、失败会话成本、崩溃后恢复总量
  • winBrain 落点：与 AgentBay /bill 合并成统一成本仪表

Todo Lists winBrain 未用

  • SDK 内置 todo 事件流（TaskCreated/TaskCompleted hooks 同步）
  • winBrain 落点：TUI/Web 渲染 Agent 长任务的实时进度清单

四大收益

收益 说明
上下文隔离 子代理独立上下文窗口，主代理不被杂物污染
并行化 多子代理同时跑不同任务，总耗时显著下降
专用指令 每个子代理专属 prompt（专业知识/风格）
工具限制 子代理级 tools 白名单（如只读）

系统提示

  • 预设 claude_code（完整 Claude Code 行为）vs 完全自定义（从零控制）
  • 自定义维度：CLAUDE.md 注入、输出风格（outputStyle）、追加、或全量替换
  • winBrain：每个场景（Creator 对话/项目聊天/专家 API）定制 systemPrompt ✅

Agent Skills / Plugins

  • Skills：.claude/skills/ 目录（用户级/项目级）；可发现、可测试、工具受限
  • Plugins：把 skills + agents + hooks + MCP servers 打包成一个单元加载
  • winBrain：员工=Skill、专家=Plugin 的模型完全对应 SDK 语义 ✅（skill-bundle-registry 已实现）

Slash Commands

  • SDK 内可用斜杠命令控制会话（如 /resume、/compact、自定义命令）
  • winBrain：AgentBay 的 /resume /sessions /bill /shutdown-all 即同思路 ✅

Hosting 官方指南

  • 子进程架构：SDK 子进程即执行单元，建议每任务隔离（进程池 + 超时回收）
  • 会话持久化：外部存储（S3/Redis）跨实例恢复
  • 水平扩展：无状态 worker 池 + 队列；观测（OTel）接入
  • 多租户隔离：Docker / Kubernetes / 沙盒提供商（如 E2B）每租户独立进程
