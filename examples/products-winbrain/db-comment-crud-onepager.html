数据库字段注释文档 CRUD，winBrain 会发生什么？

探索对象：winBrain Creator OS（Ink + Claude Agent SDK）· Data Ontology 链路 · 2026-08-13 · 基于仓库源码事实
TL;DR：改注释文档，系统默认「无感」——skill 文件不会变，但专家知道的会过期。 已发布的 Ontology MCP 是 静态快照（.pi/ontology-state.json），磁盘上改文档没有监听、没有指纹对比，release 不会自动失效。
唯一更新路径：走 TUI/Web 重新导入 → 批准草稿 → 重新发布。批准时 release 才回 draft；新 releaseId 会让旧客户端收到 ONTOLOGY_RELEASE_CONFLICT。
skill 文件（SKILL.md）本身 100% 不受影响；受影响的是专家的「运行时知识面」与「评测语料」。
0文档监听/指纹校验（发布后外部 CRUD 零感知）
5+1release 回 draft 的触发点（批准/分析/确认/映射/建图…）
4发布阻塞条件（空本体/待批草稿/待审映射/待确认字段）
2受影响层次（专家知识面 + 评测语料）≠ skill 文件

① release 状态机 核心机制

关键事实：暂存文档、生成导入草稿时 release 仍为 published；批准（approveOntologyImport）时才回 draft → 必须重新发布。客户端固定旧 releaseId 读取会得到 ONTOLOGY_RELEASE_CONFLICT，禁止混读。

// 发布阻塞（ontologyPublicationBlocker, L183）：
// ① 本体为空  ② 仍有待批准的导入草稿  ③ 仍有 pending 映射  ④ 仍有 suggested 字段标注
// release 回 draft 的触发点（mcpRelease: {status:"draft"}）：
//   approveOntologyImport L263 · analyzeOntologyAsset L315 · confirmOntologyAsset L347
//   reviewOntologyMapping L355 · buildOntologyGraph L386
// 发布（publishOntologyMcp）：mcpRelease = {status:"published", publishedAt}

② CRUD 影响矩阵 逐个操作

操作立即发生下一步（走 UI 时）skill 影响
边界与校验门（导入文档） 
validateOntologyDocuments / ontology-document-policy.ts：
  · 扩展名白名单：.md .txt .yaml .yml .sql .json（md/txt → role=material，其余 → role=schema）
  · 单文件 ≤ 256KB，总 ≤ 512KB；纯 UTF-8（拒绝 NUL / U+FFFD）
  · .json 必须可解析；文件名不得以 . 开头、不含路径分隔符
Schema Scanner（scripts/ontology-schema-scanner.py，60s 超时）：
  · 只读直连 FMCG/ARO/Video Management，读 INFORMATION_SCHEMA 注释
  · 扫描结果按「与已选 .md 注释文档同名的表」过滤，防整库混入
  · 生成 schema.. 快照文档 → 草稿 → 同发布门

③ skill 受影响吗？ 分三层看

为什么 skill 文件安全？ 
· 专家 = Plugin（skills/SKILL.md + .claude-plugin/plugin.json + mcpServers 绑定），skill 是「操作方法」静态资产
· 文档 CRUD 只改变 Data Ontology 的「数据」，不触碰专家目录任何文件
· 专家会话里的 Ontology MCP（describe_contract / search_ontology / get_ontology_item / get_app_context）
  读的是 .pi/ontology-state.json 的 release 快照 —— 数据过期与否取决于是否重新导入发布
· 发布阻塞期（有草稿/pending 映射等）describe_contract 返回 release: null → 专家「看不见」新本体

④ 行动清单 保持语义诚实

文档 CRUD 后走 UI 重新导入 —— 直接改磁盘文件，系统零感知，release 不会自动失效
批准或驳回导入草稿 —— 草稿存在时 publicationBlocker 禁止发布；驳回只是丢弃草稿，已入库数据不变
批准后重新发布 —— 批准时 release 回 draft，不重发布则 MCP 返回 NOT_PUBLISHED
删除文档前先处理草稿 —— 草稿引用的源文档被删后批准直接失败
客户端收到冲突就刷新 —— 固定旧 releaseId 读新 release 会冲突，禁止混读
（建议）发布时记录文档指纹 —— 当前实现缺这一层，属诚实性缺口
